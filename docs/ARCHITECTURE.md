# معماری پارسیا

این سند مسیر داده، فرمول‌ها و تصمیم‌های پیاده‌سازی را توضیح می‌دهد. هدف این است که هر عدد و هر ماتریس را بتوان با کد تطبیق داد.

## ۱. نقشهٔ ماژول‌ها

| فایل | مسئولیت |
|---|---|
| `parsia/text.py` | نرمال‌سازی فارسی و فیلترهای کیفیت |
| `parsia/tokenizer.py` | آموزش و اجرای BPE، کدگذاری/کدگشایی |
| `parsia/model.py` | پارامترها، پیش‌رو، پس‌رو، AdamW، استنتاج KV، نمونه‌گیری |
| `parsia/train.py` | پیکره→توکن، حلقهٔ آموزش، ارزیابی، checkpoint |
| `parsia/generate.py` | موتور استنتاج، قالب‌های گفتگو، جریان تولید |
| `parsia/thinking.py` | جست‌وجوی چندمسیره و امتیازدهی |
| `web/server.py` | FastAPI، نشست‌ها، متریک‌ها، NDJSON |
| `web/static/*` | رابط بدون فریم‌ورک |

## ۲. نرمال‌سازی فارسی

ترتیب عملیات مهم است:

1. حذف تگ‌های HTML و نشانی‌ها
2. حذف نویسه‌های نامرئی (`U+200B`, bidi controls, soft hyphen)
3. نگاشت حروف عربی به فارسی: `ي→ی`، `ك→ک`، `ة→ه`، `ى→ی`
4. ارقام فارسی/عربی → لاتین برای یکدستی
5. حذف اعراب و کشیده
6. نگه‌داشتن فقط نویسه‌های مجاز (حروف، ارقام، فاصله، نیم‌فاصله، نشانه‌گذاری)
7. اصلاح فاصله‌های اضافی و فاصلهٔ پیش از نشانه‌ها
8. کاهش تکرار نشانه‌ها (`!!!` → `!`)

تابع `prepare_user_input` همین مسیر را با محدودیت طول برای ورودی کاربر اجرا می‌کند تا توزیع آموزش و استنتاج یکی بماند.

## ۳. توکنایزر BPE

### پیش‌توکن‌سازی

```text
[\w\u200c]+[^\s\w]*   یا   [^\s\w]+
```

یعنی یک واژه (شامل نیم‌فاصله) به‌همراه نشانه‌های چسبیده، یا یک نشانهٔ مستقل. تکه‌های بلندتر از ۴۰ نویسه شکسته می‌شوند تا هزینهٔ ادغام کنترل شود.

هر تکه با نشانگر پایان واژه `</w>` بسته می‌شود؛ بنابراین «کتاب» و «کتاب.» و «کتاب‌ها» مرز خود را حفظ می‌کنند.

### آموزش

- شمارش تکرار تکه‌ها: `Counter`
- برای هر تکه، جفت‌های مجاور با وزن تکرار شمارش می‌شوند
- ایندکس معکوس `pair → set(word_ids)` نگه‌داری می‌شود تا هر ادغام فقط واژه‌های متأثر را به‌روز کند
- سبدهای شمارشی (`count → set(pairs)`) یافتن پرتکرارترین جفت را O(1) می‌کند
- توقف در ۱۰٬۰۰۰ توکن یا وقتی بیشترین تکرار کمتر از ۲ شود

### کدگذاری

برای هر تکه، در هر گام کم‌رتبه‌ترین جفت (بر اساس ترتیب ادغام) پیدا و جایگزین می‌شود. سپس هر تکه به شناسهٔ واژگان نگاشت می‌شود. توکن‌های ویژه پیش از پیش‌توکن‌سازی جدا می‌شوند و هرگز ادغام نمی‌شوند.

## ۴. مدل

### پارامترها

```
wte: (10000, 256)          امبدینگ واژه (هم‌زمان سر خروجی)
wpe: (256, 256)            امبدینگ موقعیت
برای هر لایه:
  ln1_g, ln1_b: (256,)
  qkv_w: (256, 768), qkv_b: (768,)
  attn_w: (256, 256), attn_b: (256,)
  ln2_g, ln2_b: (256,)
  mlp1_w: (256, 1024), mlp1_b: (1024,)
  mlp2_w: (1024, 256), mlp2_b: (256,)
lnf_g, lnf_b: (256,)
```

وزن `wte` با سر خروجی مشترک است (weight tying) تا پارامتر کمتری هدر رود.

### پیش‌رو

```
x₀ = wte[token] + wpe[pos]

برای هر لایه:
  a  = LayerNorm(x; γ₁, β₁)
  q,k,v = split(a·W_qkv + b_qkv)
  A = softmax((q·kᵀ)/√d + mask_causal)
  x  = x + (A·v)·W_o + b_o
  h  = LayerNorm(x; γ₂, β₂)
  x  = x + SiLU(h·W₁ + b₁)·W₂ + b₂

logits = LayerNorm(x; γ_f, β_f)·wteᵀ
```

- **ماسک علّی:** مثلث پایین ماتریس مجاز است؛ بقیه با `-inf` پر می‌شوند.
- **SiLU:** `x·σ(x)`؛ در پس‌رو از سیگمویدِ ذخیره‌شده استفاده می‌شود تا هزینهٔ `tanh/exp` دوباره پرداخت نشود. (در نسخهٔ نخست GELU با `x**3` و `tanh` بود و ~۲٫۴ برابر کندتر.)
- **LayerNorm:** میانگین و واریانس روی آخرین محور، با ε=10⁻⁵.

### پس‌رو (دستی)

برای هر لایه، به ترتیب معکوس:

1. **شاخهٔ MLP**
   `dW₂ = actᵀ·dx`، `dact = dx·W₂ᵀ`، `dhidden = dact ⊙ SiLU'(h)`، سپس `dW₁`، `db₁` و پس‌روی LayerNorm دوم.
2. **شاخهٔ توجه**
   `dW_o`، `dA = reshape(dout)`، `dv = Aᵀ·dA`، `dscores = dA·vᵀ`، پس‌روی softmax:
   `ds = A ⊙ (ds − Σ(ds⊙A))`، سپس `dq = scale·(ds·k)`، `dk = scale·(dsᵀ·q)` و `dW_qkv = aᵀ·dqkv`.
   دقت: `scale = 1/√head_dim` هم در پیش‌رو و هم در مشتق `q·kᵀ` اعمال می‌شود.
3. **اتصال باقی‌مانده:** گرادیان به ورودی بلوک اضافه می‌شود، نه جایگزین آن.
4. **امبدینگ:** `np.add.at` برای `wte` و جمع روی محور batch برای `wpe`.

### آزمون

`tests/gradcheck.py` مدل را در `float64` می‌سازد، گرادیان تحلیلی را با تفاضل مرکزی روی نمونه‌ای از درایه‌های هر پارامتر مقایسه می‌کند و خطای نسبی `< 2×10⁻⁴` را الزام می‌کند. نتیجهٔ فعلی: **۸٫۹۶×۱۰⁻⁷**.

### بهینه‌ساز

AdamW با:
- `m ← β₁m + (1−β₁)g`
- `v ← β₂v + (1−β₂)g²`
- گام با تصحیح سوگیری و `lr·m/(√v+ε)`
- weight decay فقط برای پارامترهای ماتریسی (نه LayerNorm/bias)
- برش نرم گرادیان: `g ← g·min(1, 1/‖g‖)`

## ۵. آموزش

```
برای گام t:
  lr(t) = lr_min + 0.5(lr_max − lr_min)(1 + cos(π·(t−warmup)/(total−warmup)))   اگر t ≥ warmup
  نمونه‌گیری batch تصادفی از آرایهٔ uint16 توکن‌ها
  پیش‌رو با کش کامل (برای پس‌رو)
  پس‌رو
  گام AdamW
  هر ۱۰ گام: گزارش
  هر ۱۰۰ گام: ارزیابی روی ۳ batch ثابت اعتبارسنجی
```

اندازه‌گیری سرعت با `OPENBLAS_NUM_THREADS=2` و batch=24، زمینه=256:

| مرحله | زمان |
|---|---|
| پیش‌رو + پس‌رو + گام | ~۳٫۳ ثانیه |
| توکن بر ثانیه | ~۱٬۸۹۰–۲٬۱۱۰ |
| گیگافلاپس مؤثر (۶PD) | ~۷۵–۸۳ |

سقف نظری ماتریس‌های بزرگ روی همین CPU با OpenBLAS حدود ۲۰۰ گیگافلاپس است؛ فاصلهٔ باقی‌مانده به هزینهٔ softmax واژگان (۳۰ میلیون درایه در هر گام)، LayerNorm و به‌روزرسانی پارامترها مربوط است.

## ۶. استنتاج

### حافظهٔ KV

برای هر لایه، `k` و `v` توکن‌های قبلی نگه داشته می‌شوند:

```
k_cache ← concat(k_cache, k_t)
v_cache ← concat(v_cache, v_t)
scores = q_t · k_cacheᵀ / √d
out = softmax(scores) · v_cache
```

هزینهٔ هر توکن جدید O(T) است، نه O(T²) محاسبهٔ دوبارهٔ کل دنباله. این موضوع گفتگو روی CPU را ممکن می‌کند: ~۸۰–۱۰۰ توکن بر ثانیه در حالی که آموزش هم‌زمان در حال اجراست.

### نمونه‌گیری

1. جریمهٔ تکرار روی ۹۶ توکن اخیر
2. تقسیم بر دما
3. حذف بیرون از top-k
4. هستهٔ top-p (کوچک‌ترین مجموعه با جرم ≥ p)
5. نمونه‌گیری تصادفی و محاسبهٔ `logprob` و آنتروپی برای گزارش

### توقف

تولید با رسیدن به `<|user|>`، `<|doc|>`، `<|bot|>` یا پر شدن زمینه متوقف می‌شود. `polish` فاصله‌های اضافی و جملهٔ ناتمام را اصلاح می‌کند.

## ۷. اندیشهٔ ژرف

برای هر پیام، ۴ مسیر موازی با دماهای `[0.72, 0.84, 0.94, 0.88]` و بذرهای متفاوت تولید می‌شود. هر مسیر امتیاز می‌گیرد:

```
score = mean_logprob
        − 0.75 × repetition(4-gram)
        − 0.02 × mean_entropy
        + 0.10 × persian_ratio
        + 0.07 × min(1, tokens/38)
        + 0.09 × (پایان با نشانهٔ جمله)
```

`mean_logprob` اطمینان مدل است (میانگین لگاریتم احتمال توکن‌های انتخاب‌شده)، `repetition` نسبت ۴گرام‌های تکراری، و `persian_ratio` نسبت حروف فارسی. بهترین مسیر برگزیده و همهٔ امتیازها در «اندیشه‌نامه» نمایش داده می‌شوند.

این روش **تفکر آگاهانه نیست**؛ یک جست‌وجوی چندمسیره با امتیازدهی خودکار است.

## ۸. سرور

- FastAPI + Uvicorn، همهٔ درخواست‌ها در حافظه
- قفل تک‌نخی حول مدل تا تولیدها با هم تداخل نکنند
- نشست‌ها در RAM (حداکثر ۶ نوبت)، با امکان پاک‌سازی
- `/api/chat/stream` پاسخ NDJSON با `start`/`token`/`done`
- بارگذاری دوبارهٔ خودکار checkpoint وقتی `last.npz` تازه‌تر شود (هات‌ریلود آموزشی)
- هدرهای امنیتی و CSP بدون منبع بیرونی

## ۹. تصمیم‌های مهندسی

| تصمیم | دلیل |
|---|---|
| NumPy به‌جای PyTorch | شفافیت کامل گرادیان‌ها و اجرای سبک روی CPU؛ مناسب آموزش و پژوهش |
| BPE فارسی اختصاصی | واژگان ۱۰ هزارتایی به‌جای ۲۵۶ بایت؛ کاهش طول دنباله و افزایش کیفیت مدل کوچک |
| SiLU به‌جای GELU | ~۲٫۴ برابر سریع‌تر در این پیاده‌سازی بدون افت کیفیت |
| وزن مشترک خروجی/امبدینگ | ~۲٫۵۶ میلیون پارامتر صرفه‌جویی |
| کش کامل در آموزش | سادگی و سرعت؛ حافظهٔ مصرفی در حد چند صد مگابایت |
| KV cache در استنتاج | کاهش هزینهٔ گفتگو از O(T²) به O(T) |
| ذخیرهٔ checkpoint در zip فشرده | ۲۴ مگابایت به‌جای ده‌ها مگابایت؛ قابل اجرا در استقرار رایگان |

## ۱۰. محدودیت‌های پژوهشی

- آموزش تک‌دوره‌ای/چنددوره‌ای روی پیکرهٔ کوچک، بدون دادهٔ دستوری
- نبود ارزیابی استاندارد فارسی (مانند سنجه‌های درک مطلب یا پرسش‌وپاسخ)
- نبود لایهٔ ایمنی و فیلتر محتوا
- حافظهٔ زمینهٔ ۲۵۶ توکن؛ گفتگوهای بلند قطع می‌شوند

گام‌های بعدی: مدل بزرگ‌تر، دادهٔ بیشتر، آموزش دستوری، ارزیابی استاندارد و بهینه‌سازی با GPU.
