# دامنهٔ گیت‌هاب: انتشار و تغییرهای بعدی

این فایل برای همان چیزی است که مالک خواسته: سایت روی دامنهٔ گیت‌هاب بالا باشد و هر
تغییری که بعداً بخواهد، بدون کار دستی روی همان دامنه بنشیند.

## نشانی

پس از روشن‌کردن Pages:

```
https://taymaz1391.github.io/ai/
```

نسخهٔ استاتیک چند صفحه دارد: خانه، چت (نمایشی)، تعرفه، مدل‌ها، درباره، مستندات،
دانلود، دوره، خلاصه، پشتیبانی، توسعه‌دهنده، ورود و ثبت‌نام (پیام «نسخهٔ نمایشی»).

## یک قدم دستی (فقط یک‌بار)

> **Settings → Pages → Source: GitHub Actions** را انتخاب و ذخیره کن.

چرا دستی؟ توکن این محیط اجازهٔ ساخت Pages را ندارد و درخواست
`POST /repos/Taymaz1391/ai/pages` با `403 Resource not accessible by integration`
برمی‌گردد. خودِ گردش‌کار `pages.yml` آماده است و از همان لحظه فعال می‌شود.

## بعد از فعال‌شدن

هر `push` روی `main` — یا اجرای دستی از تب **Actions → pages → Run workflow** —
سایت را می‌سازد و در حدود ۴۰ ثانیه منتشر می‌کند. متن‌ها، رنگ‌ها، صفحه‌های تازه و
دارایی‌ها همه خودکار می‌آیند؛ چیزی برای آپلود دستی نیست.

## چطور تغییر بخواهی

۱. بگو کدام صفحه و چه متنی عوض شود (همین جمله کافی است).
۲. من فایل `web/static/...` را ویرایش می‌کنم، `scripts/export_site.py` را اجرا می‌کنم
   و تغییر را روی شاخهٔ کار push می‌کنم.
۳. با merge همان تغییر به `main`، گردش‌کار `pages.yml` خودش دوباره می‌سازد و دامنه
   به‌روز می‌شود.

## محدودیت‌های نسخهٔ استاتیک

GitHub Pages فقط فایل ایستا سرو می‌کند و پایتون اجرا نمی‌کند. پس روی این دامنه:

* چت واقعی، ورود و ساخت حساب، سهمیه و پنل مدیریت **کار نمی‌کنند** و دکمه‌ها با پیام
  «نسخهٔ نمایشی» غیرفعال می‌شوند.
* «من ربات نیستم» و سد تهاجم سمت سرورند؛ در نسخهٔ استاتیک فقط ظاهرشان دیده می‌شود.
* برای دستیار کارکن، سرور را با [Deploy to Render](https://render.com/deploy?repo=https://github.com/Taymaz1391/ai)
  بالا بیاور و `apiBase` را در `web/static/config.js` به آدرس آن بده؛ سپس دوباره
  push کن.

## دامنهٔ اختصاصی

اگر دامنهٔ شخصی داری، در **Settings → Pages → Custom domain** واردش کن و رکورد
`CNAME` را به `taymaz1391.github.io` بده. فایل `CNAME` لازم نیست؛ گیت‌هاب خودش
نگهش می‌دارد.
