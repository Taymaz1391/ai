# کد تأیید ایمیل — پیکربندی واقعی

کد تأیید شش‌رقمی با `secrets` ساخته می‌شود، هشِ آن (HMAC-SHA256) ذخیره می‌شود و
خودِ کد هیچ‌جا در پایگاه‌داده نمی‌ماند. ارسال با SMTP انجام می‌شود؛ اگر SMTP
پیکربندی نشده باشد، سرویس صریح خطا می‌دهد و هیچ کدِ قلابی نمی‌سازد.

## راه ۱ — از پنل مدیریت (بدون ویرایش فایل)

`/admin` → تب **تنظیمات** → بخش **ارسال ایمیل و کد تأیید**:

1. میزبان، درگاه، نام کاربری، گذرواژه و فرستنده را وارد کن.
2. «ذخیرهٔ پیکربندی».
3. «ارسال ایمیل آزمایشی» — نتیجه بلافاصله زیر همان بخش نوشته می‌شود.

مقادیر در پایگاه‌دادهٔ سایت (جدول `settings`) ذخیره می‌شوند و گذرواژه در هیچ
پاسخ API برنمی‌گردد.

## راه ۲ — متغیر محیطی (اولویت دارد)

```bash
RAYAN_SMTP_HOST=smtp.gmail.com
RAYAN_SMTP_PORT=587
RAYAN_SMTP_USER=you@gmail.com
RAYAN_SMTP_PASS=xxxx xxxx xxxx xxxx     # گذرواژهٔ برنامه، نه گذرواژهٔ حساب
RAYAN_SMTP_FROM="رایان <you@gmail.com>"
RAYAN_SMTP_TLS=starttls                 # starttls | ssl | none
```

## سرویس‌های رایگانِ پیشنهادی

| سرویس | سهمیهٔ رایگان | میزبان / درگاه | نکته |
|---|---|---|---|
| Brevo | ۳۰۰ ایمیل در روز | `smtp-relay.brevo.com` / 587 | ساده‌ترین؛ فقط کلید SMTP لازم است |
| Gmail | ~۵۰۰ در روز | `smtp.gmail.com` / 587 | «گذرواژهٔ برنامه» لازم است و تأیید دومرحله‌ای |
| SMTP2GO | ۱٬۰۰۰ در ماه | `mail.smtp2go.com` / 2525 | برای حجم کم مناسب |
| MailerSend | ۳٬۰۰۰ در ماه | `smtp.mailersend.net` / 587 | نیاز به دامنهٔ تأییدشده برای فرستنده |

> برای فرستنده با دامنهٔ اختصاصی، رکوردهای SPF و DKIM را تنظیم کن؛ وگرنه ایمیل‌ها
> در هرزنامه می‌افتند. با فرستندهٔ Gmail این مرحله لازم نیست.

## رفتار سامانه

| وضعیت | نتیجه |
|---|---|
| SMTP تنظیم شده | کد واقعی ارسال می‌شود؛ در پاسخ API هیچ کدی نیست |
| SMTP تنظیم نشده | ثبت‌نام انجام می‌شود ولی کد ارسال نمی‌شود؛ کاربر پیام روشن می‌بیند |
| `RAYAN_EMAIL_DEV=1` | فقط برای آزمون محلی: کد در پاسخ می‌آید و ایمیلی نمی‌رود |

محدودیت‌ها: اعتبار کد ۱۰ دقیقه (`RAYAN_CODE_TTL`)، فاصلهٔ ارسال دوباره ۶۰ ثانیه
(`RAYAN_CODE_RESEND`)، حداکثر ۶ تلاش برای هر کد (`RAYAN_CODE_TRIES`).

## آزمون

```bash
pytest tests/test_v23.py -q -k "mail or verification"
```

این آزمون‌ها تضمین می‌کنند که: خطای SMTP به‌صورت خطا برگردد (نه «ارسال شد»)،
گذرواژه در پاسخ‌ها نیاید، و ذخیرهٔ پیکربندی بدون توکن CSRF رد شود.
