# ظرفیت یک تریلیون پارامتر: طرح، نه مدل آماده

**وضعیت: آموزش انجام نشده؛ مدل فعال سایت تغییر نکرده و افزایش کیفیتی اندازه‌گیری نشده است.**

طرح dense با ۱۲۸ لایه، عرض ۲۵۶۰۰، ۱۲۸ سر توجه، واژگان ۶۴۰۰۰ و زمینهٔ ۴۰۹۶، مطابق شکل وزن‌های معماری فعلی، دقیقاً **۱٬۰۰۸٬۴۱۸٬۸۶۷٬۲۰۰ پارامتر** دارد. این عدد تعداد وزن‌های طرح است، نه تعداد وزن‌های آموزش‌دیدهٔ موجود. انتخاب این ابعاد اثبات بهینه‌بودن معماری نیست.

## ابزار بهبودیافته

```sh
python -m scripts.plan_capacity
python -m scripts.plan_capacity --config configs/rayan-100b.json
python -m scripts.plan_capacity --device-memory-gb 80 --usable-fraction 0.8
python -m unittest tests.test_plan_100b tests.test_plan_capacity
```

محاسبه بدون ساخت وزن یا وابستگی به NumPy انجام می‌شود. ورودی‌های نامعتبر رد می‌شوند. برای تخمین زمان می‌توان `--aggregate-flops-per-second` را صریح داد؛ هیچ سرعت یا قیمت سخت‌افزاری به‌عنوان اندازه‌گیری واقعی پیش‌فرض نشده است.

## مقیاس نیازها

- وزن BF16: حدود **۲٫۰۲ ترابایت**؛ FP32: حدود **۴٫۰۳ ترابایت**، واحد ده‌دهی.
- وضعیت آموزش با فرض ۱۶ بایت به‌ازای پارامتر: حداقل **۱۶٫۱۳ ترابایت**، بدون فعال‌سازی‌ها و بافرها.
- فرض ۲۰ توکن به‌ازای پارامتر: حدود **۲۰٫۱۷ تریلیون توکن**؛ این داده در پروژه موجود نیست.
- تقریب 6ND: حدود **۱٫۲۲ × ۱۰ به توان ۲۶ FLOP**، نه بنچمارک اجراشده.
- سناریوی فرضی حافظهٔ ۸۰ گیگابایتی با سهم قابل‌استفادهٔ ۸۰٪: حداقل ۳۲ قطعه برای وزن‌های BF16 و ۲۵۳ قطعه برای وضعیت آموزش. این **تعداد دستگاه کافی برای اجرای آموزش نیست**؛ توجه، فعال‌سازی و ارتباطات حساب نشده‌اند.

## آنچه هنوز ساخته نشده

آموزش‌دهندهٔ توزیع‌شده، پشتیبانی عملی BF16، تقسیم تنسورها، ذخیره/بازیابی چندبخشی، پیکرهٔ کافی با مجوز، اجرای آموزش، ارزیابی کیفیت و سرویس‌دهی در این مقیاس وجود ندارند. موتور فعلی NumPy/CPU برای آن مناسب نیست. هیچ دانلود وزن آماده یا API هوش مصنوعی بیرونی انجام نشده است.

این تغییر **ابزار برنامه‌ریزی** را بهتر می‌کند، نه هوش مدل فعال را. بهبود واقعی سایت باید با پرسش‌های مستقل و آزمون مرورگری سنجیده شود؛ بزرگ‌کردن تعداد پارامتر جای آن را نمی‌گیرد.
