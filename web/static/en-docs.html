Run it, read it, extend it

Rayan is a single Python service: NumPy inference, SQLite storage, static front-end and a small admin API.

Quickstart

git clone https://github.com/Taymaz1391/ai.git
cd ai
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m web.server --host 0.0.0.0 --port 8000

Open http://localhost:8000. The first boot prints a generated admin password and stores it in data/admin.json. Override it with RAYAN_ADMIN_PASSWORD.

Environment variables that matter: RAYAN_DB (SQLite path), RAYAN_ADMIN_PASSWORD, RAYAN_ENV=prod (enables HSTS and secure admin cookies), RAYAN_ORIGINS (extra allowed CORS origins).

Architecture

  • Model — rayan/: tokenizer, transformer in NumPy, sampling, training loop.
  • Server — web/server.py: FastAPI app, chat and streaming, auth, tools, ads, plans.
  • Admin — web/admin.py: scrypt passwords, CSRF tokens, audit log, scheduler.
  • Store — web/store.py: SQLite with conversations, users, ads, settings, admin sessions.
  • Front-end — web/static/: no build step, no CDN, modular vanilla JS.

API

curl -s localhost:8000/api/status
curl -s localhost:8000/api/plans

curl -s -X POST localhost:8000/api/chat \
  -H 'content-type: application/json' \
  -d '{"message":"Hello, introduce yourself","max_new_tokens":48}'

curl -s -X POST localhost:8000/api/tools/run \
  -H 'content-type: application/json' \
  -d '{"name":"calc","args":{"expression":"2+2"}}'

Streaming lives at /api/chat/stream and returns newline-delimited JSON events: start, token, done, error. The done event also carries the tool result when one was detected.

Public endpoints: /api/health, /api/status, /api/flags, /api/plans, /api/models, /api/samples, /api/tools, /api/ads, /api/locale. Admin-only: /api/selftest and /api/download/checkpoint (weights). Admin endpoints require a session cookie and the x-rayan-csrf header on writes; anonymous calls receive 401.

Security

  • Strict CSP (script-src 'self'), COOP/CORP, nosniff, frame and referrer policies.
  • Session and guest cookies are HttpOnly, SameSite=Lax; admin cookie is SameSite=Strict.
  • Admin passwords use scrypt; login is rate-limited and locked for 15 minutes after repeated failures.
  • All mutating requests are checked against the request origin; the admin API additionally requires CSRF.
  • SQL is parameterised everywhere; ad URLs are validated and rendered escaped.
  • No third-party script, font or image is loaded — the site keeps working on restricted networks.

“Unhackable” does not exist. These measures remove the common classes of failure (XSS injection points, CSRF, brute force, open redirects in ads), and the admin-only /api/selftest verifies the deployment.

Language, video variant and privacy

The default language is Persian. An explicit browser language wins; otherwise the visitor's country is read from the hosting proxy header (cf-ipcountry or x-vercel-ip-country) and finally the browser timezone acts as a fallback signal. No external GeoIP service is called, and an optional local data/geoip.json table can override the result. The promo film follows the same decision: Persian or English, landscape, portrait or square.

Scaling

The honest answer first: one CPU process cannot serve a billion concurrent users, and no amount of Python tuning changes that. What is realistic:

  1. Stateless web tier — this service is already stateless apart from SQLite; move the database to Postgres and run N replicas behind a load balancer.
  2. Model tier — batch requests per replica, cache frequent prompts, and pin each replica to one checkpoint. For real traffic, replace NumPy inference with a quantised runtime on GPU.
  3. Queue — a bounded queue with 503 + Retry-After keeps latency honest under overload instead of collapsing.
  4. Edge — put static assets and the intro video on a CDN; they are immutable and cacheable for a year.
  5. Shedding — per-IP limits and the existing daily quotas protect the origin.

These are the same primitives large providers use; the difference is hardware count. A capacity plan for 1B concurrent users is a datacentre project, not a code change.

Limits

  • The checkpoint is 6.57M parameters; it produces short Persian text with visible repetition.
  • It only knows Persian. English UI is available; English answers are not.
  • Image generation is procedural (SVG/PNG posters), not diffusion.
  • The sandbox has 2 vCPU and no GPU; throughput is roughly 80 tokens/second per process.

Training

python data/build_corpus.py
python data/train_tokenizer.py
python -m rayan.train --steps 2400 --batch 16 --ctx 512

Corpora are public Persian datasets with recorded licences; data/corpus_stats.json keeps the counts. Metrics are appended to logs/metrics.jsonl and surfaced by /api/stats.
